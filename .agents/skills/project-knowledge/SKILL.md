# 项目知识维护

项目 MCP 和 `pnpm knowledge:cli` 使用当前 worktree。沿用官方 `bm-decide`、`bm-remember`、`bm-writing`、`bm-checkpoint`、`bm-orient`，本技能只补项目触发与来源关联规则。

## 开始与读取

开始实质开发时记下当前 HEAD，作为本任务的检查基点；查看已有改动以区分本任务与他人工作。按任务主题查相关知识，不扫描全部正文。

- 用户给出精确标识时，用当前项目的 `read_note` 直接读取；精确 checkpoint 找不到时如实报告，不替换成另一份。
- 主题检索先用 MCP `search_notes`，显式传入 `.codex/basic-memory.json` 的 `primaryProject`，优先 `compact=true`、`page_size=5`。找到候选后才读取有关正文。
- 中文查询为空、只命中旧规则或缺少预期依据时，先换一次已知术语、标题或元数据条件；仍不足时执行 `pnpm knowledge:find 超时 重试 --limit 5` 一类本地字面查询。多个词为任一词命中，不解析布尔语法；换成实际任务用词。输出含文件、状态和短摘录，按需分页。
- 回退找到的标识可再交给 MCP 读取；若索引尚未反映 Git 文件，用当前 worktree 的该文件核查并按需索引。明确区分检索遗漏、无证据和不存在。
- 依据当前规则行动前，核对来源文件、适用范围和替代关系。笔记与代码不符时说明差异；不能仅凭旧笔记反向修改代码。

只读问答保持只读。已有授权任务中的读取完成后继续任务，不因阅读知识增加一次确认。

## 收尾时按需收录和维护

有实现、配置或工程约定变化时，运行 `pnpm knowledge:check --since <任务开始的 SHA>`；该命令包含范围内提交、暂存、未暂存和未跟踪文件。复核刚合入的变更时使用合并前的 SHA。没有可靠历史基点时，说明默认检查只覆盖当前工作区，不能宣布历史知识已全部核对。

检查器只生成候选；查看 `candidates`、`unlinked`、`warnings` 及分页信息，再结合当前任务判断。文件变更并不自动证明知识失效。优先处理本次任务相关候选，保留他人无关修改。

- 值得留下的内容：已确认的工程决策及原因、稳定业务约束、可复用的排障结论。已在 README、AGENTS.md 或 DESIGN.md 维护的内容直接更新原处；知识笔记保留必要背景与来源，不复制整份说明、代码数值或日志。
- 先查是否已有相关笔记。小幅事实修订更新原笔记；真正改变决策时用官方技能记录新决策，并更新旧决策的状态和替代关系。批准状态来自明确授权，不能由“已经合并”推断。
- 作为当前参考的笔记在 frontmatter 中增加 `sources`：仓库相对的精确文件路径数组，如 `sources: [src/export-policy.mjs, docs/export-policy.md]`。MCP 写入时可用 `metadata.sources`。仅列实际核对过的来源，不使用绝对路径、通配符或外部 URL；外部材料放正文链接中。给受本次修改影响且缺来源的旧笔记补关联，不做全库补录。
- `coding_session` / `codex_session` 是不可变快照，记录当时事实；保留原文，必要时创建新 checkpoint。当前笔记也避免维护会过时的 `merged: false` 等活动状态，读取时查 Git/PR；需要留存时写明观察时间和提交。
- 没有新增持久知识时不创建笔记。不为每个任务生成 checkpoint，也不保存未经确认的推测作为现行规则。

知识变更与实现一并进入现有格式检查和 Git diff 审查。交付时简要说明实际新增、修订或废止的知识，以及未解决的相关差异。工具不可用时保留代码工作，明确知识维护未完成，不伪称已经保存。
